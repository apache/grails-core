GORM supports many-to-many relationships by defining a `hasMany` on both sides of the relationship and having a `belongsTo` on the owned side of the relationship:

[source,groovy]
----
class Book {
    static belongsTo = Author
    static hasMany = [authors:Author]
    String title
}
----

[source,groovy]
----
class Author {
    static hasMany = [books:Book]
    String name
}
----

GORM maps a many-to-many using a join table at the database level. The owning side of the relationship, in this case `Author`, takes responsibility for persisting the relationship and is the only side that can cascade saves across.

WARNING: One side must declare `belongsTo`. If neither side does, neither side writes the join table, so the relationship is not stored. GORM logs a warning at startup for such a mapping.

For example this will work and cascade saves:

[source,groovy]
----
new Author(name:"Stephen King")
        .addToBooks(new Book(title:"The Stand"))
        .addToBooks(new Book(title:"The Shining"))
        .save()
----

However this will only save the `Book` and not the authors!

[source,groovy]
----
new Book(name:"Groovy in Action")
        .addToAuthors(new Author(name:"Dierk Koenig"))
        .addToAuthors(new Author(name:"Guillaume Laforge"))
        .save()
----

This is the expected behaviour as, just like Hibernate, only one side of a many-to-many can take responsibility for managing the relationship.

A many-to-many with a `Map` on either side needs no `belongsTo` to be stored, because each `Map` side writes its own join table, so GORM logs no warning for it.

A many-to-many can also join a class to itself, with both properties on that class:

[source,groovy]
----
class User {
    String name
    static hasMany = [following: User, followers: User]
    static mappedBy = [following: 'followers', followers: 'following']
}
----

Such a mapping needs no `belongsTo`, and GORM logs no warning for it. Each of the two properties writes its own join table, so use `addToFollowing` and `removeFromFollowing`, which update both sides. Before deleting a `User`, remove it from both sides, otherwise the delete fails on a foreign key:

[source,groovy]
----
user.following.toList().each { user.removeFromFollowing(it) }
user.followers.toList().each { it.removeFromFollowing(user) }
user.delete()
----

Declaring `belongsTo` on such a class changes which table each property uses, so do not add it to a mapping that already works.
