The tenant id of a multi-tenant domain class, the `tenantId` property or the property named with `tenantId name:` in the mapping, is checked against the constraints declared on it, such as `nullable` or `maxSize`, in every multi-tenancy mode. It gets no default constraints: neither the default `nullable: false` nor the global `'*'` constraints of `grails.gorm.default.constraints`, though a `shared` constraint declared on it applies. A tenant id without declared constraints is not checked.

In `DISCRIMINATOR` mode GORM assigns the current tenant id to an instance before it is validated, so the constraints apply to that tenant id. In the following cases nothing assigns it, so the tenant id is checked as it is set on the instance, and an instance whose tenant id is declared `nullable: false` fails validation while its tenant id is not set:

* code that runs inside `Tenants.withoutId`, or in a method annotated with `@WithoutTenant`, in `DISCRIMINATOR` mode;
* `DATABASE` and `SCHEMA` mode, where GORM selects the database or schema of the current tenant and does not set a tenant id property;
* unit tests whose datastore is not configured for `DISCRIMINATOR` mode.

In `DISCRIMINATOR` mode GORM also assigns the current tenant id to the associated instances that are validated and saved with an instance: the new ones, such as a new child saved with its owner or one that a `beforeValidate` callback creates, and the ones that have changes. The constraints declared on their tenant ids are therefore checked as the owner is validated: a tenant id that breaks one of them is a validation error of the owner, and neither is saved. Inside `withoutId` nothing assigns it, so give such an instance its tenant id before saving its owner.

An associated instance that has a tenant id and no changes is not saved with its owner, so it keeps its tenant id and is checked with it. When validation does not cascade, as with `validate(deepValidate: false)` or `save(deepValidate: false)`, the associated instances are neither validated nor given a tenant id with their owner. They get the current tenant id as they are inserted or updated.

For example, here every book needs a publisher of at most 20 characters, also when it is saved inside `withoutId`:

[source,groovy]
----
class Book implements MultiTenant<Book> {
    String publisher
    String title

    static constraints = {
        publisher nullable: false, maxSize: 20
    }

    static mapping = {
        tenantId name:'publisher'
    }
}
----
