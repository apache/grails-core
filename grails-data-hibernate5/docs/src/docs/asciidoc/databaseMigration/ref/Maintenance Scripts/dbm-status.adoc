===== dbm-status

====== Purpose

Writes the number or the list of the change sets that have not run, to the standard output or a file.

====== Description

Lists the change sets that have not run, or counts them. It changes nothing in the database but the tables `DATABASECHANGELOG` and `DATABASECHANGELOGLOCK` Liquibase keeps, which it makes where they are not there, so `grails mcp --read-only` does not offer it.

Usage:
[source,console]
----
grails dbm-status [--contexts=CONTEXTS] [--dataSource=DATASOURCE] [--defaultSchema=SCHEMA] [--verbose=TRUE-OR-FALSE] [FILE]
----

Required arguments: _none_.

Optional arguments:

* `FILE` - The file to write the status to, relative to the directory of the project. It has to be inside the project and not there yet: the tool replaces no file, and when the file is outside the project or there already it stops before it opens the database. Directories of its path that are not there are made. Without it, the status is written to the standard output.
* `--contexts` - The contexts of the change sets to take, separated by commas: only the change sets of one of them are taken. Without it, the contexts `grails.plugin.databasemigration.contexts` configures, or every change set.
* `--dataSource` - The data source to work with, by its name under `dataSources` in `application.[yml|groovy]`, as `--dataSource=reports`. Without it, the default data source.
* `--defaultSchema` - The schema of the database to work in where the change log names none.
* `--verbose` - With `true`, the default, the change sets are listed; with `false` only their number is written. The option takes its value, written as `--verbose=false`: `--verbose` alone is refused, and the argument after `--verbose` is taken as its value. The value is `true` or `false`, in upper or lower case; any other is refused before the application is started, with exit code 2.

The tool runs in the application, which the build of the project starts around it, for the `development` environment. For another environment, name it in front of the name of the tool with `run-tool`, as `grails run-tool -Dgrails.env=production dbm-status`, or give it to the build, as `./gradlew -Dgrails.env=production runTool --arg=dbm-status` or `./gradlew -Dgrails.env=production dbmStatus`; after the name of the tool, `-Dgrails.env` is an argument of the tool and selects no environment.

The value of an option follows `=` or is the next argument: `--dataSource=reports` and `--dataSource reports` are the same. `grails help dbm-status` lists the options and parameters the tool takes. An option it does not take, an argument more than it takes and a required argument that is missing are refused before the application is started, with exit code 2 and one line, as `| Error dbm-status: --datasource is not one of its options. grails help dbm-status shows its options`.
