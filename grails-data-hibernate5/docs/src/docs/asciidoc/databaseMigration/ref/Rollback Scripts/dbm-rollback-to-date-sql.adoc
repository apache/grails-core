===== dbm-rollback-to-date-sql

====== Purpose

Writes the SQL to roll back the database to the state it was in at the given date and time, to the standard output or a file.

====== Description

The date is written as `yyyy-MM-dd` and the time as `HH:mm:ss`; without a time the date starts at midnight. After the date, a second argument that is not written as a time is the file, so `2026-01-31 rollback.sql` is the date and the file, and `2026-01-31 12:00:00 rollback.sql` the date, the time and the file. Changes nothing in the database.

Usage:
[source,console]
----
grails dbm-rollback-to-date-sql [--contexts=CONTEXTS] [--dataSource=DATASOURCE] [--defaultSchema=SCHEMA] DATE [TIME] [FILE]
----

Required arguments:

* `DATE` - The date to roll back to.

Optional arguments:

* `TIME` - The time of the day.
* `FILE` - The file to write the SQL to, relative to the directory of the project. Without it, the SQL is written to the standard output.
* `--contexts` - The contexts of the change sets to take, separated by commas: only the change sets of one of them are taken. Without it, the contexts `grails.plugin.databasemigration.contexts` configures, or every change set.
* `--dataSource` - The data source to work with, by its name under `dataSources` in `application.[yml|groovy]`, as `--dataSource=reports`. Without it, the default data source.
* `--defaultSchema` - The schema of the database to work in where the change log names none.

The tool runs in the application, which the build of the project starts around it, for the `development` environment. For another environment, name it in front of the name of the tool with `run-tool`, as `grails run-tool -Dgrails.env=production dbm-rollback-to-date-sql`, or give it to the build, as `./gradlew -Dgrails.env=production runTool --arg=dbm-rollback-to-date-sql` or `./gradlew -Dgrails.env=production dbmRollbackToDateSql`; after the name of the tool, `-Dgrails.env` is an argument of the tool and selects no environment.

The value of an option follows `=` or is the next argument: `--dataSource=reports` and `--dataSource reports` are the same. `grails help dbm-rollback-to-date-sql` lists the options and parameters the tool takes. An option it does not take, an argument more than it takes and a required argument that is missing are refused before the application is started, with exit code 2 and one line, as `| Error dbm-rollback-to-date-sql: --datasource is not one of its options. grails help dbm-rollback-to-date-sql shows its options`.
