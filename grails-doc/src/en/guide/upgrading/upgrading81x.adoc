=== Upgrade Instructions for Grails 8.0 to Grails 8.1

This guide outlines the changes introduced in Grails 8.1 that can affect an application upgrading from Grails 8.0.

==== 1. A `Publisher` Returned from a Controller Action Streams

Grails 8.1 streams any Reactive Streams `Publisher` that a controller action returns, such as a Reactor `Flux`, to the client as server-sent events; see xref:async#asyncStreaming[Streaming Responses]. In Grails 8.0 such a return value was ignored and the action's view rendered. A publisher that emits at most one item, such as a Reactor `Mono`, is not streamed: it is resolved and its value is the action's result, as a returned `Promise`'s value is, so a `Mono` of a `Map` is the model of the view.

===== Required Actions

For most applications **no changes are required**: an action that returned a `Publisher` in Grails 8.0 was almost certainly not relying on the view that rendered instead. An application that did can keep the previous behaviour by turning the streaming support off:

[source,yaml]
.grails-app/conf/application.yml
----
grails:
    async:
        streaming:
            enabled: false
----

A stream has no timeout unless `grails.async.streaming.timeout` sets one; neither `spring.mvc.async.request-timeout` nor the Servlet container's asynchronous request timeout applies to it, as neither applies to a Spring MVC server-sent event stream.

==== 2. GSP Preprocessing Directives

Grails 8.1 reads preprocessing settings from every `<%@ %>` page directive, rather than only the first. A later `grailsLayoutPreprocess="false"` now disables layout preprocessing even on pages that do not use the new `trimLogicLines` setting. If a page relied on a later setting being ignored, remove it or place the intended setting last.

As with `contentType`, codecs and `compileStatic`, the last value of a preprocessing setting wins. Setting names are case-insensitive and surrounding whitespace in values is ignored. Directives inside `%{-- --}%` and `<%-- --%>` comments do not take effect.

The new `trimLogicLines` setting is opt-in. See link:#pageDirectives[Page Directives] for its supported syntax and line-ending behavior.

==== 3. Forge Project Generation

Default projects consistently include Mockito with Spock. When both Grails Data for MongoDB and the synchronous MongoDB driver are selected, Grails Data owns the MongoDB URLs: development and test use embedded databases, while production uses the configured external server.

==== 4. Environment Variables Are Read Once Per Configuration

`getProperty` on `grailsApplication.config` resolves a property against the process environment before it consults the configuration, so that a variable such as `GRAILS_SERVERURL` overrides `grails.serverURL`. Grails 8.0 probed `System.getenv` with up to eight spellings of the key on every lookup. Grails 8.1 reads the environment once, when the configuration is created, and indexes the variable names, so a lookup that no variable can match is answered without touching the environment.

===== Required Actions

For applications **no changes are required**: the environment of a running JVM cannot change, so every lookup has the same answer as before.

A test that installs environment variables reflectively, with a library such as System Stubs or JUnit Pioneer, installs them before the application context is created, through the `environment` of the Gradle test task or an extension that runs before the context starts, so the configuration reads them when it is built. That is the supported approach: the configuration then behaves exactly as it does for a running application.

A test that can only install them after the application has started asks the configuration to read the environment again:

[source,groovy]
----
grailsApplication.config.refresh()
----

`refresh()` is a method of the configuration implementation rather than of the `Config` interface, so it is a call for dynamically compiled test code and may change with the implementation. It reads the environment again and merges the property sources again, which replaces a value the test set on the configuration directly wherever a property source defines the same key. Call it again once the variables are removed: the configuration keeps the environment it last read.

Two smaller differences: variable names are upper-cased with `Locale.ROOT`, as Spring does, so a key containing `i` matches its upper-cased variable under a Turkish default locale too; and `getProperty(null)` returns the default value instead of throwing a `NullPointerException`.
