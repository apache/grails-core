=== Upgrade Instructions for Grails 9 to Grails 10

This guide outlines the changes introduced in Grails 10 and the steps required to upgrade your application.

==== 1. Opt Into Spring MVC Content Negotiation for Grails Formats

Set `grails.mime.negotiation.spring: true` to resolve `request.format`, `response.format`, `withFormat` and the format
`respond` writes in with Spring MVC's content negotiation manager, and to have the `format` parameter, URL extensions and
the `grails.mime` settings of the `Accept` header decide what Spring MVC writes for an action too (see
<<springFormatNegotiation,Resolving Formats with Spring MVC Content Negotiation>>). Grails 10 keeps the negotiation of
Grails 9 by default.

[source,yaml]
.grails-app/conf/application.yml
----
grails:
    mime:
        negotiation:
            spring: true
----

The setting changes these answers, which the framework's tests record by running the same requests through both:

* *The order of the `Accept` header.* Spring MVC takes a more specific type ahead of a less specific one of equal
quality, where Grails 9 kept the order of the header: `Accept: */*, application/json` is the `json` format, where it was
`all`, and `withFormat` runs the `json` block rather than its first. A type with the `+xml` suffix no longer comes ahead
of `application/xml`: `Accept: application/xml, application/atom+xml` is `xml`, where it was `atom`.
* *Types with the `+json` and `+xml` suffixes.* A type no configured type names, such as `application/merge-patch+json`,
`application/soap+xml` or, without a `hal` format, `application/hal+json`, is the `json` or `xml` format, where Grails 9
read only the problem types of RFC 9457 so and answered any other as `all`. In `Content-Type` too: a body sent as such a
type is of the `json` format, where its `request.format` was `null`, and data binding reads it as JSON.
* *A request that accepts no configured type.* Such a request, as one that sends only `Accept: image/png`, and one whose
`Accept` header Spring cannot read, such as `Accept: application/json;q=abc`, is not acceptable: `response.format` and
`response.mimeType` are `null`, `respond` answers `406 Not Acceptable` and `withFormat` runs its `*` block, or no block,
where Grails 9 answered as for a client that accepts any type, with the `all` format, or read the header leniently. Code
that reads `response.format` or `response.mimeType` must allow for `null`.
* *The `format` parameter and URL extensions.* A format no type is configured for is not acceptable, to `respond`, which
answers `406`, and to what Spring MVC writes, where Grails 9 answered in the first configured format; `withFormat`
answers it from the `Accept` header, as for a format it has no block for. The `all` format leaves the format to the
`Accept` header: `?format=all` with `Accept: application/json` is `json`, where it was `all`. The first value of the
parameter counts.
* *What Spring MVC writes for an action.* The `format` parameter and URL extensions now decide the type of a
`ResponseEntity`, a `ProblemDetail` or another value Spring MVC writes for a request a URL mapping handles, where Spring
MVC read only the `Accept` header: `/book/show/1.json` is answered in JSON whatever the `Accept` header asks for, and
`/book/show/1.html` of an action that returns a map with `406`, since no message converter writes a map as HTML.
`grails.mime.use.accept.header: false` and `grails.mime.disable.accept.header.*` now ignore the `Accept` header for it
too.
* *Without the `all` format.* Where `grails.mime.types` does not list `all`, a request without an `Accept` header is of
the `all` format, as one that sends `Accept: */*` is, where Grails 9 gave the first configured format, so `withFormat`
runs its `*` block, or its first block, rather than the block of that format. A type of quality `0` comes after any
other, so `Accept: application/json;q=0, */*;q=0.1` is `all`, where it was `json`. `?format=all` is then an unknown
format.
* *Wildcards.* A wildcard such as `text/*` is the `all` format as before, but `withFormat` runs the first block of a
format with a type compatible with it, and `respond` answers in the first such format of the action, where Grails 9 ran
the first block and answered in the first format: `withFormat { pdf {...}; html {...} }` runs the `html` block for
`Accept: text/*`.
* *A `Content-Type` Spring cannot read.* A `Content-Type` Spring rejects, such as `application/json;charset=` or a list
of types, is of no format, where Grails 9 read it leniently as `json`.

Other requests resolve as before, among them those of browsers and those that name one configured type. A Spring MVC
endpoint, and Spring Security's filters before a URL mapping has matched a request, negotiate as before.
