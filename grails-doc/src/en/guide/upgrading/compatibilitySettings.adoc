A fix that changes the result of a call that works today can ship behind a setting, so that an application keeps its results when it takes a patch release. Such a setting keeps the previous result by default on the release lines that already exist, is turned on by default in the next minor release, and is removed in the next major release. While an application keeps the previous result through such a setting after the default has changed, it should plan to remove the setting before that major release.

This page lists every such setting. The upgrade notes of the release that adds a setting describe the change in detail.

When a collection sort would multiply the elements of a fetched bag, Grails loads the affected collection after the query instead of reading repeated elements from the joined rows. The collection is initialized before the results are returned. This can issue a separate query per instance and deferred collection, with the setting disabled as well as enabled.

| `grails.gorm.leftJoinAssociationSort`
| With `true`, a sort by a property of an association, such as `Book.list(sort: 'author.name')`, joins the association with a left join, so the sort keeps the instances whose association is `null`. With `false`, it joins the association with an inner join, which leaves those instances out. Applies to GORM for Hibernate. Explicit `false` logs a startup warning naming Grails 9. See link:upgrading.html#grails-7-0-18[Grails 7.0.18].
| 7.0.18

| `grails.converters.json.enum.format` and `grails.converters.xml.enum.format`
