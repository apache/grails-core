=== Upgrade Instructions for Grails and Related Dependencies

To ensure compatibility with Grails {version}, please review the following upgrade instructions carefully.
This guide outlines the necessary steps and warnings to upgrade your Grails project from Grails 8.x to Grails 9.

[TIP]
====
**Let your coding agent work through this guide.**
Grails publishes the `grails-9-upgrade` agent skill, which turns this guide into a migration checklist for an AI coding agent.
Extract it with the SkillsJars Gradle plugin, as xref:gettingStarted#agentSkills[Agent Skills] describes.
While the application is still on Grails 8, declare the skill with its version, since the Grails 8 BOM does not manage it:

[source,groovy,subs="attributes"]
.build.gradle
----
skill 'org.apache.grails.skills:grails-9-upgrade:{version}'
----
====

==== 1. Groovy 6

Grails 9 builds on Groovy {groovyVersion} and the matching Spock {spockVersion}; Java 21, Spring Boot {springBootVersion} and Spring Framework are unchanged from Grails 8.
The Grails BOM manages Groovy and Spock, so remove any version an application pins for them and review the https://groovy-lang.org/releasenotes/groovy-6.0.html[Groovy 6 release notes] for language changes that affect application code.

==== 2. RxGORM Runs on RxJava 3

RxGORM, the reactive variant of GORM in `org.apache.grails.data:grails-datamapping-rx`, is built on RxJava 3 instead of RxJava 1.
Its dependency is now `io.reactivex.rxjava3:rxjava`, and the RxJava 1 artifact `io.reactivex:rxjava` is no longer on the classpath of an application that only uses RxGORM.
Every RxGORM API that returned `rx.Observable` returns `io.reactivex.rxjava3.core.Observable`, and an `@RxSchedule` service method that returned `rx.Single` returns `io.reactivex.rxjava3.core.Single`.

Update the imports of every class that works with RxGORM results:

[cols="1,1",options="header"]
|===
| RxJava 1 | RxJava 3

| `rx.Observable` | `io.reactivex.rxjava3.core.Observable`
| `rx.Single` | `io.reactivex.rxjava3.core.Single`
| `rx.Subscriber` | `io.reactivex.rxjava3.core.Observer`
| `rx.Subscription` | `io.reactivex.rxjava3.disposables.Disposable`
| `rx.Scheduler`, `rx.schedulers.Schedulers` | `io.reactivex.rxjava3.core.Scheduler`, `io.reactivex.rxjava3.schedulers.Schedulers`
| `rx.functions.Func1` | `io.reactivex.rxjava3.functions.Function`
|===

The blocking helpers that tests and scripts use moved onto the `Observable` and `Single` types themselves:

[cols="1,1",options="header"]
|===
| RxJava 1 | RxJava 3

| `observable.toBlocking().first()` | `observable.blockingFirst()`
| `observable.toBlocking().single()` | `observable.blockingSingle()`
| `observable.toList().toBlocking().single()` | `observable.toList().blockingGet()`
| `single.toBlocking().value()` | `single.blockingGet()`
|===

`Observable.toList()` returns a `Single<List<T>>` in RxJava 3.
The RxGORM methods that emit a list, such as `list()`, `findAll().toList()` on a criteria query and `toListObservable()` on a lazy association, still return an `Observable<List<T>>`, so code that subscribes to them is unchanged.

Subscribing with a closure, for example `Book.get(id).subscribe { Book book -> ... }`, is unchanged.
A class that subscribes with a full subscriber implements `io.reactivex.rxjava3.core.Observer` instead of `rx.Subscriber`: it gains `onSubscribe(Disposable)`, which receives the handle that cancels the subscription, and `onCompleted()` is named `onComplete()`.
`DetachedCriteria`, `ObservableProxy` and the lazy association collections implement `io.reactivex.rxjava3.core.ObservableSource`, so their `subscribe(Observer)` method returns `void` rather than a `Subscription`; they can be passed anywhere RxJava 3 accepts an `ObservableSource`, such as `Observable.wrap(..)` or `concatWith(..)`.

RxJava 3 does not allow `null` to be emitted.
An RxGORM operation that has no result completes without emitting, as queries already did; for example `save()` on an instance the datastore did not write completes empty instead of emitting `null`.
An `@RxSchedule` service method that returns a `Single` and produces no result now signals a `java.util.NoSuchElementException`, and one that returns an `Observable` completes empty.
Replace a test that compares `toBlocking().first()` with `null` by one that expects `blockingFirst()` to throw `NoSuchElementException`, or use `firstElement().blockingGet()`, which returns `null` for an empty result.

A datastore implementation of RxGORM built for Grails 8 or earlier, such as the RxGORM for MongoDB plugin, is compiled against RxJava 1 and must be rebuilt against this release before it can be used.
The `rx-mongodb` profile feature now adds `grails-async-rxjava3` to a generated application.

==== 3. RxJava 1 and RxJava 2 Async and Events Modules Are Deprecated

The RxJava 1 and RxJava 2 implementations of the Grails promise and event bus APIs, `grails-async-rxjava`, `grails-async-rxjava2`, `grails-events-rxjava` and `grails-events-rxjava2`, are deprecated for removal.
They keep working in Grails 9 and log a warning when their promise factory or event bus is created.
Replace either dependency with the RxJava 3 module, `grails-async-rxjava3` or `grails-events-rxjava3`; the `Promise` and `EventBus` APIs an application uses are the same.
See <<asyncPromises,Promises>> and <<events,Events>>.
