[[ui-s2ui-create-challenge-questions]]
=== s2ui-create-challenge-questions

.Purpose

Generates controllers, services, domain object, views, i18N, and application configuration to have challenge questions

The general format is:

[source,bash]
----
./gradlew runTool -Pargs="s2ui-create-challenge-questions <domain-class-package> <challenge-qa-class-name> <user-domain-class-name> [number-of-questions]"
----

- domain-class-package is required and is the package where the Domain, Controller, and Services will be created.  It is recommend to use the same class where your 'User' class is created.
- challenge-qa-class-name  is required and is the Name of the domain class used to store this information
- user-domain-class-name is required and is the package and name of the User class.  It is recommend to ensure the first parameter is the same package as the User class.
- number-of-questions is optional but if not given will default to 2. It is a number of 1 or more.

For example:

[source,bash]
----
./gradlew runTool -Pargs="s2ui-create-challenge-questions com.mycompany Profile com.mycompany.User 4"
----

The command fails, and writes nothing, when it is given fewer than three or more than four arguments, a number of questions that is not a number of 1 or more, or names that are not the names of a package and of classes. Fewer than three or more than four arguments, a number of questions that is not a whole number, and an option, of which it has none, are refused before the command runs, with exit code 2 and a line that names what is wrong; a whole number below 1 is refused by the command.

The command will create one Domain Class.  This will contain a link to the user and also contain one entry for each questions and answer.  If you pass in either no package or the same package as the what is used for the Challenge Question domain it will not put a package in front of the User class. However, if you pass in a different package then it will add the package in front of the user class.

The command will create one controller which contains all the logic for handling the actions needed to provide a user interface to manage different users challenge questions and answers.

The command will create two services.  The first service is to handle to be the implementation for the controller/domain object handling the data needed to set/get questions and answers.
The second service is a listener service which ensures that anytime an answer is created or updated the value is encypted before it is stores in the database.

The command will create three views.  Each of the three views (List/index, edit, and create) will support all the CRUD operations.

The command will add lines to your `grails-app/conf/application.groovy` file in order to ensure the questions and answers are properly configured.

The command will add one line to `grails-app/i18n/messages.properties`. This will be the menu item in the nav bar for spring security.
----
spring.security.ui.menu.<challenge-qa-class-name>=<challenge-qa-class-name> Questions
----

A class or a view the application already has is kept, with a warning. The lines for `application.groovy` and `messages.properties` are added each time the command runs, so remove the earlier ones when you run it again.

The classes and the views are rendered from the templates `ChallengeQuestions*.template` of the plugin. A file of the same name the application has under `src/main/templates` is taken in place of the one of the plugin.
