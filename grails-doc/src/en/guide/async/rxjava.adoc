Grails integrates https://github.com/ReactiveX/RxJava[RxJava] 3 at three points. Each is a separate module that an application adds to `build.gradle`; Grails itself does not depend on RxJava.

==== Promises on RxJava

`grails-async-rxjava3` provides a `grails.async.PromiseFactory` backed by RxJava 3, so every `Promise` the application creates is an RxJava subscription:

[source,groovy]
.build.gradle
----
runtimeOnly 'org.apache.grails.async:grails-async-rxjava3'
----

See <<asyncPromises,Promises>>.

==== Events on RxJava

`grails-events-rxjava3` provides an `EventBus` that delivers events through RxJava 3 subjects and schedulers:

[source,groovy]
.build.gradle
----
runtimeOnly 'org.apache.grails.events:grails-events-rxjava3'
----

See <<events,Events>>.

==== RxJava Data Services

With `grails-datamapping-rx` on the classpath, a GORM data service can declare methods that return `io.reactivex.rxjava3.core.Observable` or `io.reactivex.rxjava3.core.Single`. GORM implements the method as it does any other data service method: the blocking query runs when the result is subscribed to, on the subscribing thread, and the result is delivered on RxJava's IO scheduler, so the caller consumes it reactively without the datastore itself being non-blocking:

[source,groovy]
.build.gradle
----
implementation 'org.apache.grails.data:grails-datamapping-rx'
----

[source,groovy]
----
import grails.gorm.services.Service
import io.reactivex.rxjava3.core.Observable
import io.reactivex.rxjava3.core.Single

@Service(Book)
interface BookService {

    Single<Book> findOne(String title)

    Observable<Book> findAllByTitle(String title)

    Observable<Book> findAllByAuthor(String author)
}
----

A `Single` that finds nothing signals a `java.util.NoSuchElementException`, since an RxJava 3 `Single` cannot complete without a value; an `Observable` that finds nothing completes without emitting. The `grails.gorm.rx.services.RxSchedule` annotation selects the scheduler a method delivers its result on. Neither it nor the default moves the query itself off the subscribing thread, so subscribe from a task, as <<asyncRequests,Asynchronous Request Handling>> describes, to keep a blocking query off a request thread. See the RxJava Support section of the GORM for link:{hibernate7Guide}index.html#dataServicesRxJava[Hibernate 7] or link:{hibernate5Guide}index.html#dataServicesRxJava[Hibernate 5] guide.

==== RxJava Results from Controllers

An RxJava 3 `Flowable` is a Reactive Streams `Publisher`, so an action can return one and Grails streams every item it emits to the client as a server-sent event, with no plugin. See <<asyncStreaming,Streaming Responses>>:

[source,groovy]
----
import io.reactivex.rxjava3.core.BackpressureStrategy

class BookController {

    BookService bookService

    def feed(String author) {
        bookService.findAllByAuthor(author)
                .toFlowable(BackpressureStrategy.BUFFER)
    }
}
----

Grails subscribes to the publisher on the request thread, so in this example the data service runs its query there, before the action returns, as the previous section describes; the items are then delivered on the IO scheduler and written to the response from it, with the container thread released while they are. With `subscribeOn(..)` the query runs on the IO thread instead, in the data service's own transaction, so once that transaction ends its results have no session to load lazy associations from, and anything that reads the current request, such as a tenant resolver, does not see the request on that thread.

`Observable` and `Single` are not `Publisher` instances, so returning one directly does not stream; convert it with `toFlowable(..)` as above.

To respond with a single result instead of streaming it, return a `Promise` and subscribe inside the task, as <<asyncRequests,Asynchronous Request Handling>> describes, so the request thread is released while the query runs. Use `firstElement().blockingGet()`, which returns `null` when nothing is found, so that a missing title answers 404 rather than failing the request with the `NoSuchElementException` that a `Single` signals:

[source,groovy]
----
import static grails.async.web.WebPromises.*

class BookController {

    BookService bookService

    def show(String title) {
        task {
            respond bookService.findAllByTitle(title).firstElement().blockingGet()
        }
    }
}
----

NOTE: Earlier versions of Grails offered the `rxjava` plugin (`org.grails.plugins:rxjava`) and, for RxJava 2, `org.grails.plugins:rxjava2`, which let an action return an RxJava `Observable` directly and added Server-Sent Events support. Both target Grails 3 and neither has a release for Grails 7 or later, so they cannot be used with this version of Grails. Grails now streams a `Publisher` itself, as above.
