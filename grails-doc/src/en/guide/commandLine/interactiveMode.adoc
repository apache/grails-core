When you execute the `grails` command without a command in a Grails project, the command line enters interactive mode. In this mode it functions like a shell, allowing you to run multiple commands without starting the command line again for each. This is particularly useful when working with code-generation commands (such as `create-controller`) or exploring what the command line has.

[source,console]
----
$ cd myapp
$ grails
grails> create-controller Book
grails> create-domain-class Book
grails> exit
----

Outside a project, `grails` without a command shows the help, and with `--non-interactive` it shows the help everywhere.

* Every command of the current directory can be given at the prompt, with its options, as it is given after `grails` on the command line. A line that starts with `#` is ignored.
* A line that starts with `!` runs the rest of the line in the shell of the operating system, as `!git status` does, and `!` alone runs the last command again. See link:commandLine.html#interactiveModePrograms[Running a Program of the Operating System] below.
* `exit` or `quit`, alone on its line, leaves interactive mode, as do the end of the input (Ctrl-D) and the interrupt of the terminal (Ctrl-C) at the prompt. Ctrl-C while a command runs Gradle stops Gradle and returns to the prompt, and Ctrl-C while the program of a `!` line runs is the program's.
* The commands that build, test and run commands of the project (`compile`, `test-app`, `assemble`, `run-command` and the others that are a Gradle build) are run through the Gradle Tooling API in interactive mode, where a command line of its own starts the Gradle wrapper. They ask Gradle for the build through one connection, which is made for the first of them and closed when interactive mode is left:
** *It is fast.* Nothing is started for a build after the first, so a build that Gradle has little to do for is back at the prompt in about 50 milliseconds, where starting the wrapper takes about 350.
** *Gradle writes plain text*, without its colors and its display of progress, and a line for every task.
** *A build does not read what you type*: what is typed is the next line of the prompt. A command of the application that asks a question is run by its name, as `grails NAME`, in a terminal of its own.
** *Ctrl-C cancels the build* and returns to the prompt; the Gradle daemon stays for the next build.
** `gradle`, `shell` and `run-app` start the Gradle wrapper there as everywhere, and `GRAILS_GRADLE_RUNNER=process` has every command do so. See link:commandLine.html#howGradleIsRun[How the `grails` Command Runs Gradle].
* `run-app` returns to the prompt once the application answers on its port and leaves it running, so that other commands can be given; `stop-app` stops it, and so does leaving interactive mode, before `grails` returns: like `stop-app`, it waits up to 30 seconds until nothing answers on the port of the application any more, also where a Gradle daemon runs the application. An application that `run-app --detach` started goes on after interactive mode, until `stop-app`. See link:commandLine.html#gradleBuild[Building with Gradle].
* `test-app --continuous` runs the tests again on every change until Ctrl-C cancels it, and returns to the prompt then.
* What interactive mode tells you to type, after a mistake or in a warning, is what its prompt takes: `Run 'help' for the commands` where a command line of its own says `Run 'grails help' for the commands`, and `To list them now: gradle grailsCommandCatalog` where it says `To list them now: grails gradle grailsCommandCatalog`. The prompt takes the commands themselves, and refuses `grails` in front of them as a command there is not.

NOTE: The interactive mode of the Grails shell of earlier versions had the command `open`, which opened a file with the program of the desktop. Interactive mode does not have it: a file is opened with the program of the operating system that opens files, through `!` (`!open FILE` on macOS, `!xdg-open FILE` on Linux, `!start FILE` on Windows). `exit` and `quit` leave it as they left the Grails shell, and `!` is kept, and runs its line through the shell now. Its prompt is `grails>`, and it does not say `Enter a command name to run. Use TAB for completion:` when it starts. See "Commands of Earlier Versions" in xref:commandLine[The Command Line].

One of the advantages of interactive mode is the availability of tab-completion. You can simply press the TAB key to view possible options for a given command or flag. The commands that are completed are those of the current directory as it is after the last command: once a command has made the directory a project, or has added a feature that brings a command, the commands of the project are completed without leaving interactive mode. After `feature add`, the names of the features the project does not have are completed. A shell outside interactive mode completes the commands of `grails` with the completion script of the distribution: see "Completion in a Shell" in xref:commandLine[The Command Line].

[[interactiveModePrograms]]
==== Running a Program of the Operating System

A line that starts with `!` runs the rest of the line as a command line of the operating system, as the interactive mode of the Grails shell of earlier versions did, and returns to the prompt when it has ended:

[source,console]
----
grails> !git status --short
 M grails-app/controllers/myapp/BookController.groovy
grails> !ls grails-app/domain/myapp | wc -l
       3
grails> !grep -rl TODO grails-app
| Exit code 1
grails> exit
----

* *The line goes to your shell as it was typed.* The shell is the one the `SHELL` environment variable names, when it names one by its absolute path, and `/bin/sh` otherwise, which is given the line with `-c`; on Windows it is the command interpreter that `ComSpec` names, `cmd.exe`, given the line with `/d /s /c`. Quotes, variables, patterns such as `*.groovy`, pipes and redirections are those of that shell, and a backslash is the shell's to read. The shell runs the line as it runs a script, so the aliases and functions of your interactive shell are not there.
* *It runs in the current directory of interactive mode*, the directory `grails` was started in, with the environment `grails` was started with. A `cd` or a variable that the line sets ends with the line.
* *The program has the terminal.* What it writes is shown as it writes it, it reads what you type, so an editor or a program that asks a question works, and Ctrl-C goes to the program, which ends or does what it does with Ctrl-C; interactive mode waits for the program to end and asks for the next line.
* *An exit code other than 0 is shown* in one line, `| Exit code 1`. On Linux and macOS a program that Ctrl-C ended has the exit code 130.
* *`!` alone runs the last command again*, as it did in the Grails shell: the last line that was a command of interactive mode, and not one that started with `!`. Before the first command it says that there is none to run again. Nothing else that follows `!` refers to the history: `!!` gives `!` to the shell.
* *The line is in the history* of interactive mode, which the arrow keys go through, and after the name of the program the TAB key completes the paths of the files of the current directory.
* *In lines that are piped into `grails`*, a line that starts with `!` is run as when it is typed, but the input of the program is empty: the lines after it are lines of interactive mode, and none of them is read by the program.
* *It is a line of interactive mode only.* On a command line of its own, `grails '!ls'` is refused as a command there is not, with exit code 2, and nothing is run.

The line runs with your rights, as it does when you type it in your shell: interactive mode runs what you type, and what is piped into it. Pipe into `grails` only lines you would run in a shell.

== Help and Information

You can access general usage information for Grails commands using the help flag associated with a specific command, or with the `help` command followed by the name of the command (`help create-app`); `help` alone lists the commands.
