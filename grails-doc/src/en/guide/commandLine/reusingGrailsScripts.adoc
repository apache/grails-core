A script of a project (see xref:commandLine#creatingCustomScripts[Creating Custom Scripts]) is run by the build of the project, through the Gradle task `runScriptCommand`. What it can re-use is other scripts and Ant.


==== Invoking Another Script


A script can invoke another script, of the project or of a plugin, by invoking a method that is named after it:

[source,groovy]
----
createJob('Nightly')
----

The above runs the script `create-job`, as `grails create-job Nightly` does where the script is a command. The arguments of the method are the arguments of the script.

Only a script can be invoked this way. The commands of the `grails` command line that are no scripts, such as `test-app`, `run-app` and `compile`, and the commands an application or a plugin brings as classes, such as `generate-all` of the scaffolding plugin, are not: `testApp()` in a script fails. Before Grails 9 the Grails shell ran scripts itself, and such a method ran any command of the shell. Run those commands from the command line, one after the other.


==== Invoking Gradle


A script cannot run a Gradle task: the `gradle` property that scripts had in the Grails shell, as in `gradle.compileGroovy()`, is not there, because the script already runs inside a build. Run the task before or after the script (`grails gradle compileGroovy`), or make the work a task of the build.


==== Invoking Ant


You can invoke Ant tasks from scripts, which helps with code generation and automation tasks:

[source,groovy]
----
ant.mkdir(dir:"path")
----
