Grails has a type of application for a REST API, with a more focused set of dependencies and commands than a web application. It is created with the link:{commandLineRef}create-restapi.html[create-restapi] command:

[source,console]
----
$ grails create-restapi my-api
----

The application this creates differs from the one `create-app` creates:

* It renders its responses with JSON views (see the next section): `views-json` is one of its default features.
* It has nothing that is for HTML: no GSP, no asset pipeline, no scaffolding and no Geb tests. `gsp` can be selected as a feature; `scaffolding` and `asset-pipeline-grails` are not features of this type of application.
* It has commands for REST endpoints that other applications do not have.

`create-restapi --list-features` lists the features that can be selected for a REST API application and marks the default ones. The options of the command are those of the other `create-` commands, described in xref:commandLine#creatingProject[Creating a Grails Project].

In the `grails-app/views` directory there are `*.gson` files in place of GSP pages: `application/index.gson` renders the index page, which `ApplicationController` serves, and `error.gson` and `notFound.gson` render the 500 and 404 responses.

A plugin for REST endpoints that several applications share is created with link:{commandLineRef}create-rest-api-plugin.html[create-rest-api-plugin]. It has the plugin descriptor class and the build of a plugin, is set up for JSON views and nothing for HTML as a REST API application is, and has the commands of a REST API application. Unlike the application it has an empty `UrlMappings` class and none of the controller and views above, because everything in a plugin becomes part of the applications that use it; see link:plugins.html#creatingAndInstallingPlugins[Creating and Installing Plugins].

The commands that only a REST API application and a REST API plugin have are:

[cols="2,3"]
|===
|Command |Creates

|`create-domain-resource <name>`
|A domain class that is annotated with `@Resource`, and so is a REST resource without a controller of its own, and its unit test.

|`create-restful-controller <domain class>`
|A controller for the domain class that extends `RestfulController` and responds with JSON.

|`create-functional-test <name>`
|A test under `src/integration-test/groovy` that calls the running application over HTTP.
|===

[source,console]
----
$ cd my-api
$ grails create-domain-resource my.api.Book
$ grails create-domain-class my.api.Author
$ grails create-restful-controller my.api.Author
----

The `UrlMappings` of a REST API application map the HTTP methods to the actions of a controller by its name (`get "/$controller/$id"` to `show`, `post "/$controller"` to `save`, and so on), so the controller the `@Resource` annotation gives `Book` answers at `/book` and `AuthorController` at `/author`. See link:REST.html#domainResources[Domain classes as REST resources] and link:REST.html#restfulControllers[Implementing REST controllers].

The commands link:{commandLineRef}generate-all.html[generate-all], link:{commandLineRef}generate-controller.html[generate-controller] and link:{commandLineRef}generate-views.html[generate-views] generate a REST controller, its data service, their tests and JSON views (`index.gson`, `show.gson` and a template for the class) for a domain class in a REST API application and in a REST API plugin, as they did before Grails 9. They are commands of the scaffolding plugin now, which a REST API application does not have by default: create the application with `--features scaffolding`, or add the plugin with `grails feature add scaffolding`. See link:scaffolding.html[Scaffolding].

NOTE: Before Grails 9 `generate-all` of the `rest-api` profile also wrote a functional test, which used the Micronaut HTTP client. It writes none now: link:{commandLineRef}create-functional-test.html[create-functional-test] writes a test that calls the running application over HTTP.
