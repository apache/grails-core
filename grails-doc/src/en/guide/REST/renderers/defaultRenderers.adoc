The default renderers for XML and JSON can be found in the `grails.rest.render.xml` and `grails.rest.render.json` packages respectively. These use the Grails converters (`grails.converters.XML` and `grails.converters.JSON`) by default for response rendering. 

You can easily customize response rendering using these default renderers. A common change you may want to make is to include or exclude certain properties from rendering. 


==== Including or Excluding Properties from Rendering


As mentioned previously, Grails maintains a registry of `grails.rest.render.Renderer` instances. There are some default configured renderers and the ability to register or override renderers for a given domain class or even for a collection of domain classes. To include a particular property from rendering you need to register a custom renderer by defining a bean in `grails-app/conf/spring/resources.groovy`:

[source,groovy]
----
import grails.rest.render.xml.*

beans = {
    bookRenderer(XmlRenderer, Book) {
        includes = ['title']
    }
}
----


NOTE: The bean name is not important (Grails will scan the application context for all registered renderer beans), but for organizational and readability purposes it is recommended you name it something meaningful.

To exclude a property, the `excludes` property of the `XmlRenderer` class can be used:

[source,groovy]
----
import grails.rest.render.xml.*

beans = {
    bookRenderer(XmlRenderer, Book) {
        excludes = ['isbn']
    }
}
----


==== Customizing the Converters


As mentioned previously, the default renders use the `grails.converters` package under the covers. In other words, under the covers they essentially do the following:

[source,groovy]
----
import grails.converters.*

...
render book as XML

// or render book as JSON
----

Why the separation between converters and renderers? Well a renderer has more flexibility to use whatever rendering technology you chose. When implementing a custom renderer you could use https://github.com/FasterXML/jackson/[Jackson], https://github.com/google/gson[Google Gson] or any Java library to implement the renderer. Converters on the other hand use Grails' object marshallers, and write JSON through the application's Jackson `JsonMapper`, as described below.


==== JSON Rendering With Spring Boot's JsonMapper


The JSON converter writes JSON through the application's Jackson `JsonMapper`, the one Spring Boot auto-configures, so a
Grails application and a Spring Boot application return the same JSON for the same values. The mapper writes every
single value it has a dedicated serializer for, such as dates and times, `Month`, `UUID`, `Locale`, `byte[]`, types with
a `@JsonValue` other than enums and the types of Jackson modules registered with the application, and it formats and
pretty prints the
JSON text. `spring.jackson.*` properties therefore configure `render ... as JSON` as well:

[source,yaml]
----
spring:
    jackson:
        time-zone: America/New_York
----

Domain classes are rendered by a Jackson serializer that Grails provides, as described below. Beans, enums, records,
`Optional`, collections and maps are rendered by Grails marshallers, and the values they contain as any other value is.
Enums render by `name()`, so that the JSON binds back to them, and strings are escaped for an HTML `<script>` element
(`</` is written as `<\u002f`). To render a type differently, register an object
marshaller for it, which takes precedence over the mapper, for example in `BootStrap.init`:

[source,groovy]
----
JSON.registerObjectMarshaller(Date) { Date date ->
    date.time
}
----

A serializer that a Jackson module provides, such as a `@JacksonComponent`, renders its type. The values that it writes,
such as the properties of its type, are rendered as any other value is, so object marshallers apply to them, and an
object marshaller registered for the type itself takes precedence over the serializer.

Setting `grails.converters.json.date` to `javascript` renders `java.util.Date` values as JavaScript `new Date(...)`
constructors instead. Setting `grails.converters.json.legacy` to `true` renders JSON as Grails 8 did; the upgrade guide
lists the differences.

Parsing is not affected: `JSON.parse` and `request.JSON` parse with Grails' own parser, which also accepts JSON that
strict parsers reject, such as single-quoted strings and comments.


==== Domain Classes and the JsonMapper


The JSON converter renders a domain class instance with a Jackson serializer that Grails provides:

[source,json]
----
{"id":1,"title":"Grails","publisher":{"id":3},"authors":[{"id":1},{"id":2}]}
----

* An associated domain class instance is written as a reference of its id, or in full when
`grails.converters.json.default.deep` is `true` (or within `JSON.use('deep') { }` for the converter). Rendering deep with
the mapper, an instance that is already being written further up is written as a reference.
* The version and the class name are written when `grails.converters.json.domain.include.version` and
`grails.converters.json.domain.include.class` are `true`.
* A proxy is written as the instance it proxies, and a reference to a proxy is written from its identifier, without
loading it.
* A property annotated with `@JsonIgnore`, or with `@JsonProperty(access = WRITE_ONLY)`, is not written.

The property values are rendered by the converter's marshallers. The application's `JsonMapper` itself renders domain
classes as Jackson beans, as it does any class. To have it render them as the JSON converter does, including when a
Spring MVC controller returns one or when you call `jsonMapper.writeValueAsString(book)`, set:

[source,yaml]
----
grails:
    converters:
        json:
            domain:
                jackson:
                    enabled: true
----

Grails then registers the serializer with the mapper, as the `domainClassJacksonModule` bean, which you can also add to a
`JsonMapper` you build yourself. Written by the mapper:

* The properties that `@JsonIgnoreProperties` names are left out, as Jackson leaves them out; GORM adds that annotation
to every domain class, naming properties such as `errors` and `tenantId`. The converter renders those with its includes
and excludes, as before.
* Property names follow `@JsonProperty`, `@JsonNaming` and the mapper's naming strategy, also in references. A domain
class with `@JsonTypeInfo` is written with its type id, and an instance in a `@JsonUnwrapped` property is unwrapped.
* A domain class with its own `@JsonSerialize` serializer, with a `@JsonValue`, or that implements `JacksonSerializable`
is written by Jackson.

Other Jackson annotations and settings, such as `@JsonInclude`, `@JsonView` or `@JsonFormat` on a property, do not apply
to domain classes; the upgrade guide lists them.


==== Date and Time Rendering

With the default mapper configuration, dates and times render as follows:

[cols="2,3", options="header"]
|===
| Type
| Rendered as

| `java.util.Date`, `java.sql.Date`, `java.sql.Timestamp`, `Calendar`, `XMLGregorianCalendar`
| a UTC instant with millisecond precision, such as `"2025-10-08T07:48:46.407Z"`

| `java.sql.Time`
| its wall-clock time in the JVM default time zone, such as `"01:48:46"`

| `Instant`
| ISO-8601, such as `"2025-10-08T07:48:46.407254Z"`

| `LocalDate`, `LocalTime`, `LocalDateTime`
| ISO-8601 without a time zone, such as `"2025-10-08"`, `"01:48:46.407254"`, `"2025-10-08T01:48:46.407254"`

| `OffsetDateTime`, `ZonedDateTime`, `OffsetTime`
| ISO-8601 with the offset and without a zone ID, such as `"2025-10-08T01:48:46.407254-06:00"`, `"03:00-03:00"`

| `YearMonth`, `MonthDay`, `Duration`, `Period`, `javax.xml.datatype.Duration`
| ISO-8601, such as `"2026-09"`, `"--09-25"`, `"PT1H30M"`, `"P1Y2M3D"`, `"P1DT2H"`

| `Year`, `Month`
| a number, such as `2026` or `9`

| `ZoneId`, `ZoneOffset`, `TimeZone`
| the ID, such as `"America/Sao_Paulo"` or `"-03:00"`
|===

An `OffsetTime` uses its `toString()` form, which omits zero seconds and writes fractional seconds in groups of three
digits. A `Month` renders as its number; data binding accepts both the number and the enum name. JSON views keep their
existing formats, including the enum name for `Month` and ISO-8601 formatting for `OffsetTime`.

Map keys use the mapper's key serializers, so its date format and time zone settings apply to date keys as well.
