== generate-all

=== Purpose

Generates a controller, the service it uses, their tests and the views for a domain class: GSP views, or JSON views in a REST API application

=== Examples

[source,console]
----
grails generate-all org.bookstore.Book
grails generate-all Book Author
grails generate-all "*"
grails generate-all org.bookstore.Book --force
----

=== Description

Grails supports a feature known as static scaffolding, which generates a CRUD (Create/Read/Update/Delete) interface for a domain class as source files. Once generated, the files are yours to change, and they are not updated when the domain class changes.

The `generate-all` command does what link:{commandLineRefFromRef}generate-controller.html[generate-controller] and link:{commandLineRefFromRef}generate-views.html[generate-views] do, one after the other. For the domain class `org.bookstore.Book` it writes:

* `grails-app/controllers/org/bookstore/BookController.groovy`
* `grails-app/services/org/bookstore/BookService.groovy`
* `src/test/groovy/org/bookstore/BookControllerSpec.groovy`, a unit test
* `src/integration-test/groovy/org/bookstore/BookServiceSpec.groovy`, an integration test
* `grails-app/views/book/index.gsp`, `show.gsp`, `create.gsp` and `edit.gsp`

In a REST API application it writes the same controller, service and tests for a REST resource, and in place of the GSP views:

* `grails-app/views/book/index.gson`, `show.gson` and the template `_book.gson`

See the section "JSON Views and a REST Controller" below.

The files are written from the templates of the scaffolding plugin, or from those of the project under `src/main/templates/scaffolding` where it has them (see link:{commandLineRefFromRef}install-templates.html[install-templates]).

Usage:

[source,console]
----
grails generate-all <domain class>... [--force] [--views=gsp|json]
----

Arguments:

* `domain class` - The name of a domain class of the project, which is case-sensitive, with or without its package: `Book` or `org.bookstore.Book`. Several names can be given. `*` stands for every domain class under `grails-app/domain`; quote it so that the shell of the operating system does not expand it.

Flags:

* `force` - Replace files that are there already (`--force`)
* `views` - The kind of views to generate, and of controller with them, `gsp` or `json` (`--views=json`), where the kind the application is given by itself is not the one that is wanted. The value follows `=` or is the next word: `--views=json` and `--views json` are the same.

=== JSON Views and a REST Controller

In a REST API application and in a REST API plugin the command generates what the `rest-api` profile generated before Grails 9: JSON views in place of GSP views, and a controller for a REST resource in place of a controller for pages. Which of the two an application is given is decided as follows:

* With `--views=json` it is JSON views and the REST controller, and with `--views=gsp` GSP views and the controller for pages, whatever the application has.
* Without the option it is JSON views and the REST controller when the JSON views plugin (`org.apache.grails:grails-views-gson`, the `views-json` feature) is on the class path of the application and no file under `grails-app/views` ends with `.gsp`. That is a REST API application and a REST API plugin.
* Everywhere else it is GSP views and the controller for pages. An application that has both GSP and JSON views is therefore given GSP views, as before, unless the option asks for JSON views.

link:{commandLineRefFromRef}generate-controller.html[generate-controller], link:{commandLineRefFromRef}generate-views.html[generate-views] and link:{commandLineRefFromRef}generate-all.html[generate-all] decide it the same way and take the same option, so a controller and views that are generated one after the other fit together.

A REST API application has the commands when it has the `scaffolding` feature, which it does not have by default: create it with `grails create-restapi myapi --features scaffolding`, or add the feature later with `grails feature add scaffolding`. The feature gives a REST API application the commands of the scaffolding plugin and not the plugin, which the running application has no use for.

=== Running the Command

The command is a command of the scaffolding plugin (`org.apache.grails:grails-scaffolding`), which the application has to depend on. It only reads and writes files of the project, so it is a standalone command: `grails` starts it by its name as a Java process of its own, without Gradle and without the application, with the class path the last build of the project wrote down, and the project need not compile (see "The Three Kinds of Command" in link:{guidePath}commandLine.html[The Command Line]). `run-command` and the Gradle task `runCommand` run it with the build, without the application. A REST API application with the `scaffolding` feature depends on the commands of the plugin alone (`grailsCli "org.apache.grails:grails-scaffolding-cli"`), which keeps the plugin, GSP and the fields plugin off the class path the application runs with. There are three ways to run it:

[source,console]
----
$ grails generate-all org.bookstore.Book                              <1>
$ grails run-command generate-all org.bookstore.Book                  <2>
$ ./gradlew runCommand -Pargs="generate-all org.bookstore.Book"       <3>
----
<1> By its name. The build lists the commands of the application and its plugins whenever it compiles the project, and in a project it has not compiled yet `grails` has it list them first. See "Commands of the Application and its Plugins" in link:{guidePath}commandLine.html[The Command Line].
<2> With `run-command`, which runs it with the build of the project.
<3> With Gradle alone. `--arg=generate-all --arg=org.bookstore.Book` in place of `-Pargs` gives each argument as it is.

=== Failures

A file that is there already is kept: the command warns that it skips the file and goes on. With `--force` the file is replaced.

Without a domain class the command says `No domain-class specified` and fails. With a `--views` that is neither `gsp` nor `json` it says what the option takes, writes nothing and fails. A domain class that is not found is named (`Domain class not found for name: ...`); the controllers and the views of the other classes are generated, and the command fails.

When the command fails, the Gradle task fails, and `grails` ends with exit code 1.

Before Grails 9 the Grails shell ran a script of the same name. The plugin has no scripts any more, and the command asks no questions: the name of the domain class has to be given.
