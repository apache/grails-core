== create-rest-api-plugin

=== Purpose

The `create-rest-api-plugin` command creates a Grails plugin project for plugins that provide REST endpoints: it is set up for controllers and JSON views, and has nothing for HTML. The project has the `views-json` feature in place of GSP, the asset pipeline and scaffolding. Its `UrlMappings` class is empty, and it has no controller and no views of its own, because everything in a plugin becomes part of the applications that use it: add the mappings, controllers and views the plugin is to provide.

=== Usage

[source,console]
----
$ grails create-rest-api-plugin [OPTIONS] NAME
----

The command creates a subdirectory named after the project in the directory where it is executed, or with `--inplace` creates the project in the current directory.

For a plugin that needs no web layer, use link:create-plugin.html[create-plugin], and for a plugin with GSP views link:create-web-plugin.html[create-web-plugin]. link:create-restapi.html[create-restapi] creates the REST API as an application. For more information on developing plugins, refer to the user guide section on link:{guidePath}plugins.html[Plugin Development].

=== Options

These are the options of `grails create-rest-api-plugin`:

- `NAME`: The name of the project, with or without a package: `com.example.bookstore` creates `bookstore` with the default package `com.example`.
- `-f, --features=FEATURE[,FEATURE...]`: The features to use in addition to the default ones. `--list-features` lists them.
- `--exclude-features=FEATURE[,FEATURE...]`: The features to leave out of those the project would have by default.
- `-d, --data=Grails Data Implementation` (`-g`, `--gorm` are legacy aliases): The Grails Data implementation: `hibernate5`, `hibernate7`, `mongodb`, `neo4j`.
- `-s, --servlet=Servlet Implementation`: The embedded servlet container: `tomcat`, `jetty`, `undertow`, `none`.
- `-r, --reloading=RELOADING`: The development reloading option: `devtools`, `jrebel`, `none`.
- `--jdk, --java-version=<javaVersion>`: The JDK version the project should target.
- `-i, --inplace`: Create the project in the current directory.
- `--subproject`: Create the project as a project of the Gradle build the directory is in, with the files of the application only.
- `--list-features`: Output the available features and their descriptions. See link:list-features.html[--list-features].
- `--feature-pack-dir=DIRECTORY`, `--feature-pack-repository=URL`, `--feature-pack-sha256=COORDINATES=SHA256`, `--feature-catalog=URL`, `--list-catalog-features`, `--refresh`, `--offline`: For the feature of a plugin that has a feature pack.
- `--preset=PRESET`: The preset the project is made from: a preset for the `rest-api-plugin` type, given as the coordinates of its artifact (`group:artifact:version`), as a jar or a directory by a path with a `/` in it, or by its name in a feature catalog. An option given on the command line is used in place of the one of the preset. See link:{guidePath}applicationTypes.html#presets[Making Applications from a Preset].
- `-h, --help`: Show the help of the command and exit.

Each option is described in link:{guidePath}commandLine.html#creatingProject[Creating a Grails Project], and what the types of application and their features are in link:{guidePath}applicationTypes.html[Application Types, Features and Feature Packs].

=== Examples

1. Create a REST API plugin in a new `bookstore` directory:
+
[source,console]
----
$ grails create-rest-api-plugin bookstore
$ cd bookstore
----

2. Create a REST API plugin with options and features:
+
[source,console]
----
$ grails create-rest-api-plugin com.example.bookstore \
    --jdk=21 \
    --data=hibernate7 \
    --servlet=jetty \
    --features=asciidoctor,github-workflow-java-ci
----

3. Create a REST API plugin in the current directory:
+
[source,console]
----
$ mkdir bookstore
$ cd bookstore
$ grails create-rest-api-plugin --inplace
----

4. List the features that can be selected:
+
[source,console]
----
$ grails create-rest-api-plugin --list-features
----
