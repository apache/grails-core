== create-command

=== Purpose

The `create-command` command creates a command of the application: a class that is run in the application, with the `grails` command or as a Gradle task.

=== Examples

[source,console]
----
grails create-command MyExample
grails create-command data-import
----

=== Description

Usage:

[source,console]
----
grails create-command [-f] <<name>>
----

Creates `grails-app/commands/<package>/<Name>Command.groovy`, a class that implements link:{apiFromRef}org/apache/grails/core/cli/GrailsApplicationCommand.html[GrailsApplicationCommand], from the template `artifacts/Command.groovy`. It is a command of every project.

The name is needed: the command does not ask for one. It can include a package, such as `org.bookstore` in the last example above; without one, the class goes into the default package of the project. The first letter of the name is made upper case.

Options:

* `-f`, `--force` - Replace a file that is there already. Without it the command writes nothing when one of its files exists, says which, and ends with exit code 1.

The name can be given with hyphens (`data-import` becomes `DataImportCommand`), and a name that ends with `Command` already is taken without it.

The command that was created is a command of `grails` by its name with hyphens, as are the commands of the plugins the application depends on. The command says the name in its last line:

[source,console]
----
$ grails create-command MyExample
| Rendered command to grails-app/commands/com/example/MyExampleCommand.groovy
| Run it with: grails my-example
$ grails my-example
----

The build has not listed the new command yet, so `grails my-example` has it list the commands of the application and its plugins first, which compiles the project; a build that compiles the project lists it as well. `run-command`, which takes an environment in front of the name, and the Gradle task run the same command:

[source,console]
----
grails run-command my-example
./gradlew runCommand -Pargs="my-example"
----

Scripts created with `create-script` do not have access to the running application. A command of the application is run with the application started around it, so it can use its beans and its classes. See link:{guidePath}commandLine.html#creatingCustomCommands[Creating Custom Commands].

See "Creating Classes with the `grails` Command" in link:{guidePath}commandLine.html[The Command Line] for the names the command takes, what it does when a file is there already, and how a project replaces the template.
