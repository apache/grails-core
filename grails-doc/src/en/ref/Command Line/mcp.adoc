== mcp

=== Purpose

Serves the commands of `grails` and the tools of the application and its plugins to an AI agent, as a server of the Model Context Protocol (MCP) on its standard input and output. An MCP client starts it; it is not typed.

=== Examples

[source,console]
----
claude mcp add grails -- grails mcp
claude mcp add --scope project grails -- ./grailsw mcp
claude mcp add shop -- grails mcp --directory apps/shop
claude mcp add grails-readonly -- grails mcp --read-only
----

The same server in the `.mcp.json` of a project, which Claude Code reads, and in `.cursor/mcp.json` for Cursor:

[source,json]
----
{
  "mcpServers": {
    "grails": {
      "command": "./grailsw",
      "args": ["mcp"]
    }
  }
}
----

=== Description

Usage:

[source,console]
----
grails mcp [--directory=DIR] [--read-only]
----

Options:

* `--directory` - The directory to serve, in place of the working directory the client starts the server in. A server serves one directory for its whole session; another project gets a server of its own.
* `--read-only` - Offer only the tools that change nothing, and not `refresh_tools`: for an agent that should look at a project and not change it.

`grails mcp` speaks the revision 2026-07-28 of the Model Context Protocol, through the MCP Java SDK, on its standard input and output; it binds no socket. Its standard output carries the protocol and nothing else, and what it says for you goes to its standard error. A client that speaks only an earlier revision of MCP, and so begins with `initialize`, is answered with the error `-32022`.

Each call of a tool runs one `grails --plain-output --non-interactive` command line in the process of the server, as interactive mode runs a line, with one connection to Gradle and the project generator kept for the session. The tools are the commands of the directory as `help --json` lists them, without those that need a terminal or a person (`shell`, `console`, `gradle`, `help`, `bug-report`, the deprecated names), and every tool of the application and its plugins except one that declares that it reads what is typed. `refresh_tools`, the server's own tool, has the build list the tools of the application and its plugins again. The resources are `grails://commands`, `grails://tools/{name}`, and in a project `grails://project` and `grails://project/health`.

Started by hand, with a terminal as its input, `mcp` writes one line on the standard error that says how a client registers it, and then serves its input. At the prompt of interactive mode it is refused with exit code 2, and through `GrailsCli.execute` in the JVM of another program with exit code 1. It ends with exit code 0 when the client closes its input or sends it SIGINT or SIGTERM, and with exit code 1 after it had to give up three calls that did not stop.

The scripts that start the command line do not give `mcp` the option `-XX:TieredStopAtLevel=1` they give a command, because the server runs for a whole session.

See link:{guidePath}commandLine.html#mcp[Driving Grails from an AI Agent] for registering a client, what is offered and how a call runs, safety, and troubleshooting.
