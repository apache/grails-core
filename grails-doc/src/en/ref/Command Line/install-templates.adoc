== install-templates



=== Purpose


Copies the the templates used by Grails during code generation to your project directory


=== Examples


[source,groovy]
----
grails install-templates
----


=== Description


Usage:

[source,groovy]
----
grails install-templates
----

The `install-templates` command will copy the templates Grails uses for all code generation activities to the application's `src/main/templates/scaffolding` directory.


== Gradle runCommand install-templates

=== Purpose

Copies the templates used by Grails during code generation to your project directory

=== Examples

[source,console]
----

=== Description

Usage:

[source,console]
----
$ ./gradlew runCommand -Pargs="install-templates"

The `install-templates` command will copy the templates Grails uses for all code generation activities to the application's `src/main/templates/scaffolding` directory.

== Grails Forge CLI install-templates

=== Purpose

Copies the templates of the code generation commands of the Grails Forge CLI to your project directory

=== Examples

[source,shell]
----
grails install-templates
grails install-templates --force
----

=== Description

The `install-templates` command of the Grails Forge CLI copies the templates of the commands the project has, such as `create-controller`, `create-service` and `create-unit-test`, to `src/main/templates/artifacts` and `src/main/templates/testing` of the project (and `src/main/templates/Job.groovy` in a project with the Quartz plugin). Those commands then write their files from the templates of the project. It lists each file it writes; a template the project has already is kept and named unless `-f` or `--force` is given.

It does not write the scaffolding templates under `src/main/templates/scaffolding`, which the command of the scaffolding plugin described above copies.

See "Templates of the Project" in link:{guidePath}commandLine.html[The Command Line] for the templates and their syntax.
