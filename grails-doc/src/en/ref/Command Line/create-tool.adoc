== create-tool

=== Purpose

The `create-tool` command creates a tool of the application: a class that the `grails` command runs by its name, in the build of the project or, with `--standalone`, as a process of its own.

=== Examples

[source,console]
----
grails create-tool DataImport
grails create-tool --standalone CreateReport
grails create-tool org.bookstore.data-import
----

=== Description

Usage:

[source,console]
----
grails create-tool [-f] [--standalone] <<name>>
----

Without `--standalone`, creates `src/cli/groovy/<package>/<Name>Tool.groovy`, a class that implements `ApplicationTool` and `ToolSupport` of the package `org.apache.grails.core.cli`, from the template `artifacts/Tool.groovy`. The build of the project runs such a tool, with the classes of the project and with the application started around it; a tool that does not need the running application declares `boolean startsApplication = false`.

With `--standalone`, creates `src/standalone/groovy/<package>/<Name>Tool.groovy`, a class that implements `StandaloneTool` and `ToolSupport`, from the template `artifacts/StandaloneTool.groovy`. The `grails` command runs such a tool as a Java process of its own, without Gradle and without the application, also while the project does not compile; it has the files of the project and not its classes. Choose it for a tool that only reads and writes files of the project.

It is a command of every project. As it is written, the class prints its name and the arguments it was given and returns `true` from `handle()`, so the new tool runs and succeeds at once; its work replaces that body, and `handle()` returns `false` to end the tool with exit code 1.

The name is needed: the command does not ask for one. It can include a package, such as `org.bookstore` in the last example above; without one, the class goes into the default package of the project. The first letter of the name is made upper case.

Options:

* `--standalone` - Write a standalone tool into `src/standalone/groovy`, in place of a tool into `src/cli/groovy`.
* `-f`, `--force` - Replace a file that is there already. Without it the command writes nothing when one of its files exists, says which, and ends with exit code 1.

`create-tool` has no short form, so it is only typed with its whole name: `cT` and `ct` are `create-taglib`, as in Grails 8, and `cTo` and `cto` are no command.

The name can be given with hyphens (`data-import` becomes `DataImportTool`), and a name that ends with `Tool` already is taken without it.

The tool that was created is run by its name with hyphens, as are the tools of the plugins the application depends on. The command says the name in its last line:

// TOOLS-VERIFY: the output of create-tool (P4).
[source,console]
----
$ grails create-tool DataImport
| Rendered tool to src/cli/groovy/com/example/DataImportTool.groovy
| Run it with: grails data-import
$ grails data-import
----

The build has not listed the new tool yet, so `grails data-import` has it list the tools of the application and its plugins first, which compiles the project; a build that compiles the project lists it as well. `run-tool`, which takes an environment in front of the name, and the Gradle task run the same tool:

[source,console]
----
grails run-tool data-import
./gradlew runTool --arg=data-import
----

A project of Grails 8 that has its own template `src/main/templates/artifacts/Command.groovy` has it read for `create-tool` without `--standalone`, with a warning: rename it to `artifacts/Tool.groovy`. `create-tool` never writes into `grails-app/commands`, where Grails 8 put its classes, or a class that implements the deprecated `ApplicationCommand` or `GrailsApplicationCommand`. `create-command` of Grails 8 is no command any more: `grails create-command` is refused with exit code 2 and a line that names `create-tool`. Script commands, the scripts in `src/main/scripts`, are deprecated as well, and no command creates a new one.

See link:{guidePath}commandLine.html#creatingTools[Creating Tools] for where a tool goes and what each kind can use, and "Creating Classes with the `grails` Command" in link:{guidePath}commandLine.html[The Command Line] for the names the command takes, what it does when a file is there already, and how a project replaces the template.
