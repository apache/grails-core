== test-app

=== Purpose

Runs all Grails unit and integration tests and generates reports. The command returns appropriate response codes for embedding with continuous integration servers.

=== Examples

[source,console]
----
grails test-app
grails test-app Foo
grails test-app Foo Bar
grails test-app --unit
----

=== Description

Usage:

[source,console]
----
grails test-app [--unit] [--integration] [--clean] [--continuous] [--debug-jvm] [--tests=<<name>>]... [-Dname=value]... [<<names>>...] [-- <<gradle arguments>>]
----

Executes the Grails unit and integration tests located in the `src/test/groovy` and `src/integration-test/groovy` directories: the Gradle task `test` and, where the project has a `src/integration-test` directory, `integrationTest`, for the test environment unless `-Dgrails.env=NAME` after the command names another one. By default all tests are executed, but you can specify the names of the tests as arguments, as class names or as patterns:

[source,console]
----
grails test-app *Foo*
grails test-app *Foo* *Bar*
----

The first example will execute a test called `FooSpec.groovy` whilst the second will execute `FooSpec.groovy` and `BarSpec.groovy` if they exist.

A name is looked for among the unit tests and among the integration tests, and the tests are run where they are found: a test that is among the unit tests alone does not fail the integration tests, nor the other way round. The command ends with 1 when neither has a test for a name, and Gradle names the filter that matched nothing. With `--unit` or `--integration` the name has to be that of a test of that phase. In a project whose build does not have the Grails Gradle plugin of Grails 9, Gradle fails the test task that has no test for the name (`No tests found for given includes`); say which tests are meant with `--unit` or `--integration` there.

The task of finding tests that match the pattern you provide is passed to Gradle. Take a look at the section in their docs titled link:https://docs.gradle.org/current/userguide/java_plugin.html#test_filtering[Test filtering] for more information.

Options:

* `--unit` - Run the unit tests: the task `test`.
* `--integration` - Run the integration tests: the task `integrationTest`.
* `--clean` - Run every test again, also where nothing changed: `cleanTest` and `cleanIntegrationTest` come first.
* `--continuous` - Run the tests again whenever a file they depend on changes: the continuous build of Gradle, which runs the tests when it starts.
* `--debug-jvm` - Start the JVM of the tests suspended, waiting for a debugger on port 5005.
* `--tests=NAME` - Another way to name a test; can be given more than once.
* `-Dname=value` - A system property for the build. Can be given more than once.

`--unit`, `--integration`, `--clean`, `--continuous` and `--debug-jvm` are also taken with one dash, as the command of earlier versions took them.

What follows `--` is given to Gradle as it is. See the user guide section on link:{guidePath}commandLine.html#gradleBuild[Building with Gradle] for the details.

See the link:{guidePath}testing.html[Testing] section for examples on how to combine the different options to target tests.
