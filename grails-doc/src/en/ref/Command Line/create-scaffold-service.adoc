== create-scaffold-service

=== Purpose

Creates a service that is scaffolded for a domain class with `@Scaffold`

=== Examples

[source,console]
----
grails create-scaffold-service org.bookstore.Book
grails create-scaffold-service Book --extends=org.bookstore.BaseService
----

=== Description

Dynamic scaffolding generates the actions and the views of a controller, or the methods of a service, when the application runs, for a class that is annotated with `@Scaffold` (see link:{guidePath}scaffolding.html[Scaffolding]).

The `create-scaffold-service` command writes such a service. For the domain class `org.bookstore.Book` it writes `grails-app/services/org/bookstore/BookService.groovy`. It writes no test.

Usage:

[source,console]
----
grails create-scaffold-service <domain class> [--extends=<class>] [--force]
----

Arguments:

* `domain class` - The name of one domain class. A domain class of the project is found by its simple name or its full name, and what is created goes into its package. A class the project has no source of, which is a domain class of a plugin or of another project of the build, is given by its full name.

Flags:

* `extends` - The full name of the class the scaffolded service extends
* `force` - Replace files that are there already (`--force`)

=== Running the Command

The command is a command of the scaffolding plugin (`org.apache.grails:grails-scaffolding`), which the application has to depend on, and it runs in the application, started by the Gradle task `runCommand` of the project. In a REST API application with the `scaffolding` feature, which has the commands of the plugin and not the plugin (`grailsCli "org.apache.grails:grails-scaffolding-cli"`), a class this command writes can extend a class of the scaffolding plugin, such as `RestfulServiceController` or `GormService`. It compiles, and the running application does not have that class: declare `implementation "org.apache.grails:grails-scaffolding"` in such an application first. There are three ways to run it:

[source,console]
----
$ grails create-scaffold-service org.bookstore.Book                              <1>
$ grails run-command create-scaffold-service org.bookstore.Book                  <2>
$ ./gradlew runCommand -Pargs="create-scaffold-service org.bookstore.Book"       <3>
----
<1> By its name. The build lists the commands of the application and its plugins whenever it compiles the project, and in a project it has not compiled yet `grails` has it list them first. See "Commands of the Application and its Plugins" in link:{guidePath}commandLine.html[The Command Line].
<2> With `run-command`, which also takes an environment in front of the name.
<3> With Gradle alone. `--arg=create-scaffold-service --arg=org.bookstore.Book` in place of `-Pargs` gives each argument as it is.

=== Failures

A file that is there already is kept: the command warns that it skips the file and goes on. With `--force` the file is replaced.

Without a domain class the command says `No domain-class specified` and fails.

When the command fails, the Gradle task fails, and `grails` ends with exit code 1.

Before Grails 9 the Grails shell ran a script of the same name. The plugin has no scripts any more, and the command asks no questions: the name of the domain class has to be given.
