== bug-report



=== Purpose


The bug-report command packages up the sources of your application (excluding jars, static resources etc.) into a ZIP file. The file name includes the application name and a timestamp. This is useful for reporting issues to the https://github.com/apache/grails-core/issues[Grails Issue Tracker]

=== Examples


[source,groovy]
----
grails bug-report
----


=== Description


Usage:
[source,groovy]
----
grails bug-report
----


=== Grails Forge CLI


The Grails Forge CLI has the same command. Its ZIP file holds every file under `grails-app` and `src`, and `build.gradle`: the configuration under `grails-app/conf` is in it as it is, and the command names the `application*.yml`, `application*.groovy` and `application*.properties` files it put into the ZIP file before it says what it created, so look through them for passwords before attaching it. Links are not followed. Left out are files that are keys or lists of secrets by their name (such as `.env`, `*.jks`, `*.p12`, `*.pem`, `*.key`, `id_rsa*`, `credentials*`, `secrets*`, `.netrc`, and copies of them that end with `.bak`, `.old` or `~`), directories named `build` or `.gradle` at any depth, files that have another name elsewhere on the file system (hard links), and files with a control character in their name. An existing ZIP file of the same name is replaced only with `--force`, and nothing is written when the sources are more than 10000 files or more than 256 MiB. See the user guide section on link:{guidePath}commandLine.html#gradleBuild[Gradle] for the details.
