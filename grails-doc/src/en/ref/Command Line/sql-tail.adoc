== sql-tail

=== Purpose

Shows the SQL statements a running application executes, grouped by the controller and action that
ran them, so that the pages running the most queries, and the queries repeating within one request,
stand out. The application must be started with capture turned on; see
link:{guidePath}conf.html#sqlTail[Finding Query-Heavy Pages with sql-tail].

=== Examples

[source,groovy]
----
grails run-app --sql-tail         // in one terminal: run the application with capture on

grails sql-tail                   // in another: the pages, refreshing as requests are served
grails sql-tail --statements      // the statements themselves, the most run first
grails sql-tail --page=book/show  // the statements of one page
grails sql-tail --stream          // every statement as it runs, grouped by request
grails sql-tail --all --once      // a report of everything captured so far, then exit
----

=== Description

Usage:

[source,groovy]
----
grails sql-tail [--statements | --stream] [--page=<controller/action>] [--top=<n>] [--all] [--once] [--file=<path>]
----

Without options the command follows the capture and shows the pages, the ones running the most
statements per request first: for each page how many requests were seen, the average and the
highest number of statements per request, the total, and the statement that repeated most within a
single request. The summary refreshes as statements run; press Ctrl-C to stop.

Arguments:

* `statements` - Rank the statements themselves instead of the pages that run them, with how often each ran and on how many pages.
* `stream` - Print every statement as it runs, with a header for each request, instead of a summary.
* `page` - Only the statements of one page, given as `controller/action` or as a controller name; implies `--statements`.
* `top` - How many rows to show. Defaults to 30.
* `all` - Read what the application has run so far, not only what it runs from now on.
* `once` - Print the summary of what has been captured and exit, which with `--all` is a report of the whole run so far.
* `file` - The capture file. Defaults to the one the application writes, `build/sql-tail/capture.log` or the file `grails.gorm.sqlTail.file` names. A build directory moved in `build.gradle` is followed by the application but not by this command, which runs outside Gradle: name the file in `grails.gorm.sqlTail.file` or give it here.

The command does not start the application, and it is not a reason to boot it: it runs without
the application context and only reads the capture file. When there is no capture yet it waits for
one and says how to start the application so that it writes one. Statements run outside a web
request, by a scheduled job for example, are shown under the thread that ran them.
