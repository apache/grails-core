== feature add

=== Purpose

Adds features to the application in the current directory: its files and its record become those of an application that was created with them.

=== Examples

[source,console]
----
grails feature add grails-quartz
grails feature add grails-quartz,views-json
grails feature add postgres
grails feature add postgres --diff
grails feature add mysql --replace
grails feature add grails-quartz --dry-run
grails feature add postgres --dry-run --json
----

=== Description

Usage:

[source,console]
----
grails feature add [--dry-run] [--diff] [--json] [--replace] [--feature-pack-dir=DIRECTORY]... [--feature-pack-repository=URL]... [--offline] <<feature>>[,<<feature>>...]...
----

Arguments:

* `feature` - The names of the features to add, as the `create-` commands list them with link:list-features.html[--list-features]. Several are separated by commas or spaces.

Options:

* `--dry-run` - Say which files would be added, changed and removed, which features would be replaced, and which conflicts there are, and change nothing.
* `--diff` - Show the changes that would be made to the files, as a diff, and change nothing.
* `--json` - With `--dry-run`: write what adding the features comes to as one JSON document for a tool to read, and nothing else: the outcome, the reason, the files with their paths in the project and what would be done to each, and whether the change can be made.
* `--replace` - Replace a feature that was asked for by name with the feature that takes its place, as `mysql` takes that of a `postgres` the application was created with. Without it only a feature the application has by default is replaced. It changes nothing when no such feature is in the way, and it does not choose between features of one exclusive group that are named together: those are refused.
* `--feature-pack-dir=DIRECTORY` - The directory of a feature pack that is not part of Grails and that the application was generated with from a directory, or of the preset it was made from. Its content has to have the SHA-256 the record has. Can be given more than once.
* `--feature-pack-repository=URL` - A Maven repository to fetch the jar of a plugin from, whose feature pack the application was generated with, or of its preset: `https`, or `file:` for a directory. When the option is given, only the repositories it names are asked; without it, those of `GRAILS_REPO_URL`, Maven Central and then the repository the record names for the jar. Can be given more than once.
* `--offline` - Ask nothing of the network: such a jar is taken only from a repository that is a directory.

`feature add` is the `add` command of the `feature` command. It works from the record of the project in its `.grails` directory, so it is a command of a project that Grails 9 generated. An application whose record link:project-migrate.html[project migrate] wrote for an application that was there is refused and nothing is changed: its record has no copy of what the generator wrote, to tell the changes of a feature from yours. The record of an application that an earlier version of Grails 9 generated is refused too, with `project migrate`, which moves it to the version that runs; afterwards a feature is added, and where the application is not what that version generates, the difference is kept as a change of yours. The files you changed keep your changes. When a feature changes what you changed too, or a file it writes is there already, nothing is written and the files are named. A feature the application already has is left as it is.

A feature that takes the place of one the application has by default replaces it: `postgres` replaces `h2`, the default database driver, and `grails-layout` replaces `sitemesh3`. The dependency and the configuration of the default are taken out, those of the feature are put in, the record no longer lists the default, and the command says which feature it replaced. Lines of the default that you changed, such as the URL of the H2 database, are a conflict like any other. A feature that was asked for by name, when the application was created (`create-app --features h2`) or with an earlier `feature add`, is not replaced by adding another alone: the command refuses with exit code 2, names both features and the `--replace` option, and changes nothing. With `--replace` it is replaced as a default is, the command says which features it replaced, and the record is that of an application that was created with the new feature in the place of the old one. A feature that another feature of the application requires is not replaced, with the option or without, and the feature that requires it is named. `--replace` does not choose between features that are named together: two features of one exclusive group in one command, as `feature add h2,postgres`, are refused with exit code 2, with `--replace` or without and whichever of them the application has. A command that was carried out changes nothing when it is run again. A feature that would change an option the application was created with (`--servlet`, `--data`, `--reloading`, `--jdk`) is refused, with `--replace` too, and so is the feature of a feature pack that is not part of Grails.

With `--dry-run --json` the command writes one JSON document on the standard output and nothing else. Its `outcome` is `no-changes`, `changes`, `conflicts`, `refused`, `invalid-record` or `failed`, its `reason` a code that says why for every outcome but the first two, `applicable` whether the change can be made, and `files` every file by its exact path in the project with the `action` the list above shows for it. The exit code is the one the command ends with without `--json`. `--json` without `--dry-run`, or with `--diff`, is a mistake in the command line (exit code 2). See link:{guidePath}commandLine.html#changeResultsForAProgram[The Result of `feature add` and `project regenerate` for a Program] for every member, outcome and reason.

An application that has the feature of a feature pack that is not part of Grails gets a feature of Grails only with that very pack, since it is generated again with it: the jar of a plugin is fetched again by the coordinates, the version and the SHA-256 its record has, and says so before it is asked for; the pack of a directory is given again with `--feature-pack-dir`, and its content has to have the SHA-256 the record has. A pack that is missing or is another is refused with exit code 1, and nothing is changed. See link:{guidePath}plugins.html#forgeFeaturePackAfterCreation[After the Application Is Created].

See "Adding a feature to a project" in link:{guidePath}commandLine.html#creatingProject[Creating a Grails Project] for what is merged, what is a conflict and what is refused.
