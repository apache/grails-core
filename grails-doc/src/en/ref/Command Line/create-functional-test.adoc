== create-functional-test

=== Purpose

The `create-functional-test` command creates a functional test for the given base name: a test of the running application from outside, with a browser (Geb) in a web application and with an HTTP client in a REST API application.

=== Examples

[source,console]
----
grails create-functional-test Book
grails create-functional-test org.bookstore.Book
----

=== Description

Usage:

[source,console]
----
grails create-functional-test [-f] <<name>>
----

Creates a functional test, `src/integration-test/groovy/<package>/<Name>Spec.groovy`. What the test is depends on the project:

* In a web application or web plugin that has a Geb feature it is a Geb test that opens the home page in a browser and checks its title, from the template `FunctionalSpec.groovy`. With the `geb-with-testcontainers` feature, which a web application has by default, the test extends `ContainerGebSpec` and the browser runs in a container; with the `geb-with-local-browsers` feature it extends `GebSpec` and runs a browser of the machine. It is the test the feature writes when the application is created, under the name that is given.
* In a REST API application or REST API plugin it is a test that requests the home page of the running application with the HTTP client of the JDK, which needs no further dependency, from the template `testing/Functional.groovy`.

In a project that is neither, such as a web application that was created without Geb, it is no command; `grails feature add geb-with-testcontainers` adds the feature, and the command with it, also where the dependency on the Geb plugin was written into `build.gradle` by hand. An application that has no record gets one from `grails project migrate`, which finds the Geb feature in the build: `geb-with-local-browsers` where the build declares the browser drivers that feature adds, and `geb-with-testcontainers` where it declares the Geb plugin without them.

Before Grails 9 the Geb test was written by a script of the Geb plugin, which the plugin no longer has: the command needs the record of the project to list the feature, not the plugin on a class path, and it does not start the application or its build.

The name is needed: the command does not ask for one. It can include a package, such as `org.bookstore` in the last example above; without one, the class goes into the default package of the project. The first letter of the name is made upper case.

Options:

* `-f`, `--force` - Replace a file that is there already. Without it the command writes nothing when one of its files exists, says which, and ends with exit code 1.

A name that ends with `Spec` already is taken without it: `create-functional-test BookSpec` and `create-functional-test Book` both write `BookSpec.groovy`. The script of the Geb plugin wrote `BookSpecSpec.groovy` for the first.

A project can replace the template with its own: `src/main/templates/FunctionalSpec.groovy` for the Geb test, whichever of the two Geb features the project has, which is where a project had its own copy of the template of the Geb plugin, and `src/main/templates/testing/Functional.groovy` for the test of a REST API project. `FunctionalSpec.groovy` names what it wants as `${className}` and `${packageName}`; it is text in which those names are replaced and is not run as a Groovy template, so code between `<%` and `%>` and expressions that are more than a name are refused.

See "Creating Classes with the `grails` Command" in link:{guidePath}commandLine.html[The Command Line] for the names the command takes, what it does when a file is there already, and how a project replaces the template.
