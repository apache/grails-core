== schema-export



=== Purpose


Uses Hibernate's SchemaExport tool to generate DDL or export the schema.
NOTE: As of Grails 3, the Hibernate plugin is not by default on the build classpath. You need to add it to the build classpath to get the tool working.


=== Examples


[source,groovy]
----
//Add Hibernate to the build classpath
buildscript {
    dependencies {
        classpath "org.grails.plugins:hibernate:4.3.8.0"
    }
}
----


[source,groovy]
----
grails run-tool schema-export
grails run-tool schema-export --datasource=lookup
grails run-tool -Dgrails.env=production schema-export
grails run-tool -Dgrails.env=development schema-export
grails run-tool -Dgrails.env=production schema-export export
grails run-tool -Dgrails.env=production schema-export export --datasource=auditing
grails run-tool -Dgrails.env=production schema-export stdout
----


=== Description


Usage:
[source,groovy]
----
grails run-tool [-Dgrails.env=<<environment>>] schema-export <<action>> ['stdout'] <<filename>> [--datasource]
----

Arguments:

* `environment` - The environment containing the database configuration to use (`development`, `production`, etc...), given as `-Dgrails.env` before the name of the tool. `schema-export` is a tool of the Hibernate plugin, which `grails schema-export` runs in the application; an environment is named in front of the name with link:run-tool.html[run-tool].
* `action` - Either 'generate' or 'export'.  The default is 'generate'. Both write the DDL to the file; 'export' does not run it against the database.
* `stdout` - Passing 'stdout' will cause the script to dump the ddl to stdout.
* `filename` - The name of the file to write the ddl to.  The default is ddl.sql in the project's 'build' directory. The DDL is added to the end of a file that is there.
* `datasource` - The `DataSource` name suffix; defaults to the default `DataSource` if not specified

The action, `stdout` and the file name can be given in any order, at most one of each.




== Gradle runTool `schema-export` Tool

=== Purpose

The `schema-export` tool uses Hibernate's SchemaExport tool to generate Data Definition Language (DDL) or export the schema. You need to add it to the build classpath for this tool to work properly.

=== Examples

[source,groovy,subs="attributes+"]
build.gradle
----
repositories {
    mavenCentral()
    maven { url = "https://repo.grails.org/grails/restricted/" }
}
dependencies {
    classpath 'org.apache.grails:grails-bom-hibernate5'
    classpath 'org.apache.grails:grails-hibernate5'
}
----

[source,console]
----
$ ./gradlew runTool -Pargs="schema-export"
$ ./gradlew runTool -Pargs="schema-export --datasource=lookup"
$ ./gradlew -Dgrails.env=prod runTool -Pargs="schema-export"
$ ./gradlew -Dgrails.env=dev runTool -Pargs="schema-export"
$ ./gradlew -Dgrails.env=prod runTool -Pargs="schema-export export"
$ ./gradlew -Dgrails.env=prod runTool -Pargs="schema-export export --datasource=auditing"
$ ./gradlew -Dgrails.env=prod runTool -Pargs="schema-export stdout"
----

=== Description

Usage:

[source,console]
$ ./gradlew -Dgrails.env=<<environment>> runTool -Pargs="schema-export <<action>> ['stdout'] <<filename>> [--datasource]"

Arguments:

* `environment` - The environment containing the database configuration to use (e.g., dev, prod).
* `action` - Can be either 'generate' or 'export', with the default being 'generate'. Both write the DDL to the file; 'export' does not run it against the database.
* `stdout` - Including 'stdout' will cause the script to output the DDL to the standard output (stdout).
* `filename` - Specifies the name of the file to write the DDL to, with the default being 'ddl.sql' in the project's 'build' directory. The DDL is added to the end of a file that is there.
* `datasource` - The `DataSource` name suffix; defaults to the default `DataSource` if not specified.
