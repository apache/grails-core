== schema-export

=== Purpose

Writes the DDL script that creates the schema of the database of a data source, as Hibernate's `SchemaExport` makes it from the domain classes of the application, to a file and, with `stdout`, to the standard output. Nothing is executed against the database. It is a tool of the Hibernate plugin, of both lines of GORM for Hibernate, which an application with the plugin has without another line in its build.

=== Examples

[source,console]
----
grails schema-export
grails schema-export --datasource=lookup
grails schema-export stdout
grails schema-export build/schema.sql
grails run-tool -Dgrails.env=production schema-export
grails run-tool -Dgrails.env=production schema-export --datasource=auditing build/auditing.sql
----

=== Description

Usage:

[source,console]
----
grails schema-export [--datasource=DATASOURCE] [ACTION] [STDOUT] [FILE]
grails run-tool -Dgrails.env=ENVIRONMENT schema-export [--datasource=DATASOURCE] [ACTION] [STDOUT] [FILE]
----

Arguments:

* `ACTION` - `generate`, the default, or `export`, which is accepted and does the same as `generate`: both write the DDL script to the file, and to the standard output with `stdout`. Nothing is executed against the database.
* `STDOUT` - `stdout` writes the DDL to the standard output as well.
* `FILE` - The file to write the DDL to, relative to the directory of the project; `ddl.sql` in the build directory of the project, `build/ddl.sql`, when not given. The DDL is added to the end of a file that is there.
* `--datasource` - The data source whose schema is written, by its name under `dataSources` in `application.[yml|groovy]`, as `--datasource=lookup`; the default data source when not given. The option is written in lower case, unlike the `--dataSource` of the `dbm-*` tools.

The action, `stdout` and the file name can be given in any order, at most one of each: a word that is neither `generate`, `export` nor `stdout` is the file.

The tool runs in the application, which the build of the project starts around it, for the `development` environment; `-Dgrails.env` in front of its name, with `run-tool`, gives it another one, whose data source configuration it reads. After the name of the tool, `-Dgrails.env` is an argument of the tool and selects no environment. `grails help schema-export` lists the option and the parameters, and an option the tool does not take, or a fourth argument, is refused before the application is started, with exit code 2.

The tool runs with the Gradle task `runTool` as every tool of the application does, so a build script or a continuous integration job runs it with Gradle alone:

[source,console]
----
./gradlew runTool --arg=schema-export
./gradlew runTool --arg=schema-export --arg=--datasource=lookup
./gradlew -Dgrails.env=production runTool --arg=schema-export --arg=stdout
./gradlew -Dgrails.env=production runTool -Pargs="schema-export --datasource=auditing build/auditing.sql"
----
