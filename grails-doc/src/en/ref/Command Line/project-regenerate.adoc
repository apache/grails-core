== project regenerate

=== Purpose

Generates the application in the current directory again as its record says it was generated, and changes nothing in it.

=== Examples

[source,console]
----
grails project regenerate --output ../shop-as-generated
grails project regenerate --diff
grails project regenerate --diff --json
----

=== Description

Usage:

[source,console]
----
grails project regenerate [--output=<<directory>>] [--force] [--diff] [--json] [--feature-pack-dir=DIRECTORY]... [--feature-pack-repository=URL]... [--offline]
----

Options:

* `-o`, `--output=DIRECTORY` - The directory to write the application to, which is made when it is not there. One that has anything in it is refused without `--force`.
* `-f`, `--force` - Write into a directory that has files, and overwrite those the application has.
* `--diff` - Write nothing, and name the files of the application that are not those it was generated with: those that were added, removed and changed. What the `.gitignore` it was generated with leaves out is not looked at, and neither is `.git`. Ends with exit code 1 when there are such files.
* `--json` - With `--diff`: write the files that are not those the application was generated with as one JSON document for a tool to read, and nothing else, with the outcome of the comparison and, when there is none, the reason.
* `--feature-pack-dir=DIRECTORY` - The directory of a feature pack that is not part of Grails and that the application was generated with from a directory, or of the preset it was made from. Its content has to have the SHA-256 the record has. Can be given more than once.
* `--feature-pack-repository=URL` - A Maven repository to fetch the jar of a plugin from, whose feature pack the application was generated with, or of its preset: `https`, or `file:` for a directory. When the option is given, only the repositories it names are asked; without it, those of `GRAILS_REPO_URL`, Maven Central and then the repository the record names for the jar. Can be given more than once.
* `--offline` - Ask nothing of the network: such a jar is taken from the copy of it that is kept in `.grails/forge/packs` of the home directory since it was fetched, or from a repository that is a directory.

`project regenerate` is the `regenerate` command of the `project` command. It works from the record of the project in its `.grails` directory, with the version of Grails whose record the project has. The record of an earlier version is refused, with the command that moves it to the version that runs, link:project-migrate.html[project migrate]. An application whose record `project migrate` wrote for an application that was there was not generated by this version: it is generated as its record says what it is taken to be, so `--output` writes a new application of the same type, options and features, and `--diff` names every file the application has otherwise than that new one, which is what an earlier version of Grails generated otherwise as well as what was changed since; a line says so. A record that `project migrate` wrote without a baseline is refused. An application with the feature of a feature pack that is not part of Grails is generated again with that very pack, as link:feature-add.html[feature add] takes it.

With `--diff --json` the command writes one JSON document on the standard output and nothing else. Its `outcome` is `no-changes` or `changes` when the comparison was made, with `files` listing each file by its exact path in the project and its `status` (`added`, `removed` or `changed`), and `refused`, `invalid-record` or `failed` when it was not, with a `reason` that says why: a project another version generated (`other-generator`), a record that is missing or cannot be read (`no-record`, `unreadable-record`), a baseline that the generator does not give again (`baseline-differs`), a file or a directory of the project that cannot be read (`unreadable-file`), and the others. The exit code is the one the command ends with without `--json`: 0 for `no-changes`, and 1 for every other outcome. `--json` without `--diff` is a mistake in the command line (exit code 2). See link:{guidePath}commandLine.html#changeResultsForAProgram[The Result of `feature add` and `project regenerate` for a Program] for every member, outcome and reason.

See "How a project was generated, and generating it again" in link:{guidePath}commandLine.html#creatingProject[Creating a Grails Project] for the details.
